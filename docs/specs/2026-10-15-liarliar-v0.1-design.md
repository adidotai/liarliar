# liarliar v0.1 — design

*Liar liar, tests on fire.* Coding agents say "done" when they are not. liarliar makes them prove it.

Status: approved in conversation 2026-10-15 (approach A, sections 1–3). This file is the written spec.

## Problem

An agent edits code, then reports "Fixed, all tests pass" without running the tests, after running them only
before its last edit, or after watching them fail. The user believes it and ships broken code. Prompts like
"verify before saying done" help, but nothing checks that the agent actually did it.

## What v0.1 is

1. **A skill** (`skills/liarliar/SKILL.md`, ~400 words) that requires every completion claim to end with a
   receipt: each claim, the exact command run after the last edit, and the output that proves it. Anything
   unchecked goes under UNVERIFIED. The receipt ends with a verdict.
2. **Two small hook files** (~100 lines together, Node 18+ stdlib only):
   - `hooks/judge.mjs`: all the logic as pure functions, with no I/O.
   - `hooks/liarliar.mjs`: the I/O entry point, with two modes:
     - `log` (PostToolUse / PostToolUseFailure): appends what actually happened to a per-session ledger.
     - `gate` (Stop): reads the agent's final message and blocks the finish if the receipt is missing or lies.
3. **Packaging** so it installs with one command on Claude Code, and as a skill (no hooks) everywhere else.

Out of scope for v0.1: eval cases, the Lie Rate benchmark, hook ports to Codex/Cursor, a GitHub Action.

## The receipt

A fenced code block whose info string is `receipt`:

```receipt
TASK     <one line: what was asked>
CLAIM    <what is claimed>
  $ <exact command that was run>
  > <output line that proves it>
UNVERIFIED
  - <claim>: <why it could not be checked> (user can run: <command>)
VERDICT  GO | GO WITH UNVERIFIED | NO-GO
```

Cited commands are the lines starting with `$`. A receipt without a `VERDICT` line is not a receipt.

## The ledger

- Path: `<os.tmpdir()>/liarliar-<uid or username, sanitized>/<session_id with non [A-Za-z0-9_-] removed>.jsonl`.
  The folder is created 0700 and the files 0600, so users on a shared `/tmp` cannot read or block each other.
  `LIARLIAR_DIR` overrides the folder. One JSON object per line; line order is time order.
  (Final-review fix.)
- Entries:
  - `{"k":"run","cmd":"<command>","ok":true|false}`, from Bash or PowerShell, since Claude Code on Windows often runs
    commands through its PowerShell tool. PostToolUse is `ok:true`. PostToolUseFailure is `ok:false`, unless
    `is_interrupt` is true, in which case nothing is logged. A `run_in_background` launch is not logged either,
    because it has no result yet.
  - `{"k":"edit","file":"<path>"}`. From Edit, Write, MultiEdit, NotebookEdit.
  - `{"k":"block"}`. Written by the gate when it blocks.
  - `{"k":"stop"}`. Written by the gate when it lets the agent stop. This marks the end of a turn.
- File edits made through Bash (e.g. `sed -i`) are not counted as edits. This is a documented limitation.

## The gate (Stop hook)

The final message comes from `last_assistant_message`, which was verified on CLI v2.1.217. If the field is absent
(older CLIs), the message counts as empty, so the gate lets the agent stop. There is no transcript parsing.

The gate lets the agent stop (exit 0, then append `stop`) when any of these hold:

- `LIARLIAR=off` in the environment.
- `stop_hook_active` is true and there are already 2 `block` entries since the last `stop`. This is the self-cap;
  Claude Code's own 8-continuation cap backs it up.
- Any exception. The gate fails open.

Otherwise the gate checks the message.

**A receipt is demanded** (lie 1) only when both of these hold:
- the ledger has an `edit` since the last `stop`;
- the message makes a completion claim.

The claim pattern is case-insensitive and word-bounded: done, fixed, finished, complete(d), resolved, implemented,
shipped, works/working now, test(s)/check(s)/spec(s)/suite/build [are/is/now/all/should/will] pass(ed/es/ing) or
green, ready to merge/ship/commit/deploy. Questions and explanations are never asked for a receipt.

**A receipt that is present** (a `receipt` block with a `VERDICT` line) **is always checked**, whatever the turn did
and whatever the prose says. Writing one opts in. This closes the "Implemented." + fake receipt gap found in final
review.

A `NO-GO` verdict is never a false "done", so lies 2–5 apply only when the verdict is not `NO-GO`. The gate blocks
(append `block`, write the reason to stderr, exit 2) on the first lie it finds:

| # | Lie | Rule |
|---|-----|------|
| 1 | No receipt | Demanded (see above), and there is no `receipt` block, or one without a `VERDICT` line |
| 2 | Ghost command | A cited command matches no `run` in the ledger. It matches when the whitespace-normalized run contains the cited command (equality included) |
| 3 | Stale proof | The cited command's matching runs all come before the last `edit` |
| 4 | Fail sold as pass | The latest matching run after the last edit has `ok:false`. The message notes that proof must exit 0 on success (e.g. `! grep -q`) |
| 5 | Proof-free GO | Plain `GO` (not `GO WITH UNVERIFIED`) with no cited command. Final-review fix |

Block messages are factual statements, not commands, because the hooks docs warn that imperative text can trip
prompt-injection defences. They stay under 1,000 characters. Example: "liarliar: the receipt cites `npm test`, but
no such command ran in this session. Each claim cites a command run after the last edit, or goes under
UNVERIFIED."

`hooks/judge.mjs` exports these pure functions, which the tests call directly:
- `entryFor(input)`: the ledger entry for a hook input, or `null`.
- `parseLedger(text)`: the ledger entries; malformed lines are skipped.
- `judge(message, ledger)`: `null`, or the reason string.
- `decide(input, ledger, env)`: adds the off switch and the block cap on top of `judge`.

`hooks/liarliar.mjs` only reads stdin, reads and appends the ledger file, and sets the exit code. The ledger
directory can be overridden with `LIARLIAR_DIR`, which the tests use.

## Hook wiring (`hooks/hooks.json`)

- PostToolUse, matcher `Bash|PowerShell|Edit|Write|MultiEdit|NotebookEdit`: `node "${CLAUDE_PLUGIN_ROOT}/hooks/liarliar.mjs" log`
- PostToolUseFailure, matcher `Bash|PowerShell`: same command.
- Stop: `node "${CLAUDE_PLUGIN_ROOT}/hooks/liarliar.mjs" gate`

Shell form with a quoted path works in both Git Bash and PowerShell. If `node` is missing, the command fails with a
non-2 exit code, which is non-blocking, so the user still gets the skill.

A probe on CLI v2.1.217 (Windows) confirmed:
- `${CLAUDE_PLUGIN_ROOT}` is substituted.
- A failing Bash command fires PostToolUseFailure with `error: "Exit code N"` and `is_interrupt: false`.
- A passing one fires PostToolUse.
- Stop receives `stop_hook_active` and `last_assistant_message`.


Two context-file decisions, both verified on v2.1.217:
- A root `CLAUDE.md` makes `claude plugin validate --strict` fail when it is run on the plugin.
- v2.1.217 does not read `AGENTS.md` by itself, and `@` imports from CLAUDE.md did not load reliably.

So `.claude/CLAUDE.md`, which Claude Code loads and the validator ignores, holds one sentence pointing to
`AGENTS.md`.

There is no version-bump script. Instead, a test asserts that every manifest has the same `version`.

## Install paths

| Where | Command | What you get |
|---|---|---|
| Claude Code (in session) | `/plugin marketplace add adidotai/liarliar` then `/plugin install liarliar@liarliar` | skill + hooks |
| Claude Code (shell; what an agent runs) | `claude plugin marketplace add adidotai/liarliar && claude plugin install liarliar@liarliar` | skill + hooks |
| ~70 other agents | `npx skills add adidotai/liarliar` | skill only |
| Gemini CLI | `gemini extensions install https://github.com/adidotai/liarliar` | skill only |

**Paste-the-link path.** The first line of the README tells AI agents to follow `INSTALL.md`. INSTALL.md says:
detect the harness, run the matching command, never copy files by hand (that drops the hooks), confirm with
`claude plugin list`, then tell the user to run `/reload-plugins` or restart.

## Testing

1. **Unit** (`node --test`, written before the code):
   - Each of the five lies blocks.
   - Pass-through cases: no edits since the last stop, no claim, a valid receipt, all-UNVERIFIED, NO-GO with a
     failing command.
   - `LIARLIAR=off`; malformed stdin fails open; blocking stops after 2 blocks.
   - `log` writes correct entries for PostToolUse Bash, PostToolUseFailure Bash (including `is_interrupt`), and
     Edit/Write.
   - Every manifest has the same version.
2. **`claude plugin validate --strict .`** passes.
3. **End-to-end:** `claude -p --plugin-dir <liarliar>` runs on a throwaway repo with a hidden failing test. Confirm the
   gate fires, blocks an unreceipted "done", and the final answer carries a real receipt. Record whether v2.1.217
   sends `last_assistant_message` and fires PostToolUseFailure.
4. **Install:** `claude plugin marketplace add <local liarliar>` + `claude plugin install liarliar@liarliar` +
   `claude plugin list`, then uninstall and remove the marketplace so the user's global setup is unchanged.

CI runs layers 1 and 2 on Windows, macOS and Linux.

## Dogfooding

`.claude/settings.json` declares the repo directory as a marketplace (relative path) and enables
`liarliar@liarliar`. Anyone who opens the repo in Claude Code and trusts the folder works under liarliar. The exact
settings shape is confirmed empirically with `claude plugin marketplace add . --scope project`.

## Known limitations (v0.1)

- Enforcement is Claude Code only. Other agents get the skill as instructions.
- Bash-made file edits are not seen as edits.
- The claim pattern can match negated phrases ("not done yet"). The cost is at most 2 extra receipt requests.
- Command matching is textual. An agent could run a trivial command and cite it. The receipt still shows the user
  exactly what ran, so the lie becomes visible instead of silent.
- The proof is the exit code. `npm test | tail` exits with `tail`'s code, so a failing suite piped into `tail` looks
  like a pass. SKILL.md tells agents to use `set -o pipefail;`, and the README lists the limit.
- Headless `claude -p` does not load the repo's own plugin from `.claude/settings.json`; that was verified. Whether
  it loads in a trusted interactive session is unverified.
