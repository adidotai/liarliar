# liarliar v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship liarliar v0.1: a skill plus two Claude Code hooks that stop a coding agent from saying "done" unless a receipt proves it. It must install with one command and work as a skill in other agents.

**Architecture:**
- `hooks/judge.mjs` holds every rule as pure functions.
- `hooks/liarliar.mjs` is a thin I/O entry point with two modes:
  - `log` (PostToolUse/PostToolUseFailure) appends to a per-session JSONL ledger in the OS temp dir.
  - `gate` (Stop) blocks with exit 2 when the final message claims done and the receipt is missing or lies.
- The repo is its own Claude Code marketplace (`liarliar@liarliar`), with skill-only manifests for Codex, Cursor and Gemini.

**Tech Stack:** Node 18+ (stdlib only: `node:fs`, `node:os`, `node:path`, `node:child_process`, `node:test`), Claude Code plugin system (CLI v2.1.217), GitHub Actions.

**Spec:** `docs/specs/2026-10-15-liarliar-v0.1-design.md`

**Working directory for every command:** `<repo>` (bash). The repo already exists with one commit; its git identity is set to `Aditya Abhiram <the author's personal email>`.

**Scratch directory** (throwaway files outside the repo):
`<scratch>`. It is called `$S` below.

## Global Constraints

- Node 18+ stdlib only. Zero dependencies, no `package.json`, no network calls, no telemetry, no install scripts.
- The plugin name and the marketplace name are both `liarliar`, so the install id is `liarliar@liarliar`. Version `0.1.0` appears in all four manifests.
- GitHub `adidotai/liarliar`, author `Aditya Abhiram`, license MIT.
- Hooks fail open: any error exits 0. Exit 2 means only a confirmed lie.
- Limits and switches:
  - `MAX_BLOCKS = 2`
  - off switch `LIARLIAR=off`
  - ledger dir override `LIARLIAR_DIR`
  - default ledger dir `<os.tmpdir()>/liarliar`
- Block messages are factual statements, not commands, and stay under 1,000 characters.
- SKILL.md frontmatter keys must come from `name`, `description`, `license`, `compatibility`, `metadata` and `allowed-tools`. The description is one line of at most 1,024 characters.
- No root `CLAUDE.md`, because it fails `claude plugin validate --strict`. Claude Code reads `.claude/CLAUDE.md`.
- LF line endings everywhere (`.gitattributes`). Committed files contain no absolute paths, so the folder can be moved out of `Laya_jev`.

## Review Focus

The five unexercised inputs most likely to bite real users. Each now has a pinning test in the task that owns the code:

1. **CRLF final messages.** A message with `\r\n` line endings must still parse its receipt. Test in Task 1.
2. **A decorated citation.** The receipt cites `npm test 2>&1` but `npm test` ran. This is pinned as a ghost-command block: receipts must copy commands exactly, as SKILL.md says. Test in Task 1.
3. **Latest run wins.** A command passed after the last edit, then failed on a later run. The verdict GO must be blocked. Test in Task 1.
4. **Fence and verdict spelling.** `` ```Receipt `` and `VERDICT: GO` (with a colon) are accepted. Test in Task 1.
5. **Missing `session_id`.** The hook still works, using `unknown.jsonl`. Test in Task 2.

```js
// liarliar's rules, as pure functions. No I/O here: hooks/liarliar.mjs does the reading and writing.

const RUN_TOOLS = new Set(["Bash", "PowerShell"]);
const EDIT_TOOLS = new Set(["Edit", "Write", "MultiEdit", "NotebookEdit"]);
const CLAIM = /\b(done|fixed|finished|completed?|resolved|(?:tests|checks) (?:now )?pass(?:ed|es|ing)?|ready to (?:merge|ship|commit|deploy))\b/i;
const RECEIPT = /```receipt[^\n]*\n([\s\S]*?)```/i;
const RULE = "Each claim cites a command run after the last edit, or goes under UNVERIFIED.";
export const MAX_BLOCKS = 2;

const norm = (s) => String(s ?? "").trim().replace(/\s+/g, " ");
const clip = (s) => (s.length > 120 ? `${s.slice(0, 120)}…` : s);
const sinceLastStop = (ledger) => ledger.slice(ledger.findLastIndex((e) => e.k === "stop") + 1);

/** The ledger entry for a PostToolUse / PostToolUseFailure input, or null if it is not worth recording. */
export function entryFor(input) {
  const args = input?.tool_input ?? {};
  if (RUN_TOOLS.has(input?.tool_name)) {
    const cmd = norm(args.command);
    const failed = input.hook_event_name === "PostToolUseFailure";
    return !cmd || (failed && input.is_interrupt) ? null : { k: "run", cmd, ok: !failed };
  }
  if (EDIT_TOOLS.has(input?.tool_name)) return { k: "edit", file: args.file_path ?? args.notebook_path ?? "" };
  return null;
}

/** Ledger entries from JSONL text. Blank, malformed and incomplete lines are skipped. */
export function parseLedger(text) {
  return String(text ?? "").split("\n").flatMap((line) => {
    try {
      const e = JSON.parse(line);
      return typeof e?.k === "string" && (e.k !== "run" || typeof e.cmd === "string") ? [e] : [];
    } catch {
      return [];
    }
  });
}

/** Why the agent's final message must not end the turn, or null if it may. */
export function judge(message, ledger) {
  const text = String(message ?? "");
  if (!sinceLastStop(ledger).some((e) => e.k === "edit") || !CLAIM.test(text)) return null;

  const receipt = text.match(RECEIPT)?.[1];
  if (!receipt || !/^\s*VERDICT\b/m.test(receipt)) {
    return "liarliar: the last message says the work is done, but it has no receipt. A receipt is a code block " +
      "with the info string `receipt` that lists each CLAIM with the `$ command` that proves it, puts anything " +
      "unchecked under UNVERIFIED, and ends with VERDICT GO, GO WITH UNVERIFIED or NO-GO. The liarliar skill has the full format.";
  }
  if (/^\s*VERDICT\b[:\s]*NO-GO\b/m.test(receipt)) return null; // an honest NO-GO is never a false "done"

  const lastEdit = ledger.findLastIndex((e) => e.k === "edit");
  for (const [, cited] of receipt.matchAll(/^\s*\$\s+(.+)$/gm)) {
    const cmd = norm(cited);
    const runs = ledger.flatMap((e, i) => (e.k === "run" && e.cmd.includes(cmd) ? [{ ...e, i }] : []));
    if (!runs.length) return `liarliar: the receipt cites \`${clip(cmd)}\`, but no such command ran in this session. ${RULE}`;
    const fresh = runs.filter((e) => e.i > lastEdit);
    if (!fresh.length) return `liarliar: \`${clip(cmd)}\` last ran before the most recent file edit, so it says nothing about the current code. ${RULE}`;
    if (!fresh.at(-1).ok) return `liarliar: the latest run of \`${clip(cmd)}\` failed, but the verdict is not NO-GO. ${RULE}`;
  }
  return null;
}

/** The Stop-hook decision: a block reason, or null to let the agent stop. */
export function decide(input, ledger, env = {}) {
  if (env.LIARLIAR === "off") return null;
  const blocks = sinceLastStop(ledger).filter((e) => e.k === "block").length;
  if (input?.stop_hook_active && blocks >= MAX_BLOCKS) return null;
  return judge(input?.last_assistant_message, ledger);
}
```

`hooks/liarliar.mjs`:
```js
#!/usr/bin/env node
// liarliar hook entry point.
//   log  (PostToolUse, PostToolUseFailure): record what actually ran or changed.
//   gate (Stop): let a "done" stand only if its receipt holds up.
// Fails open: any error exits 0, so liarliar can never break a session.
import { appendFileSync, mkdirSync, readFileSync } from "node:fs";
import { tmpdir } from "node:os";
import { join } from "node:path";
import { decide, entryFor, parseLedger } from "./judge.mjs";

try {
  const input = JSON.parse(readFileSync(0, "utf8"));
  const dir = process.env.LIARLIAR_DIR || join(tmpdir(), "liarliar");
  const file = join(dir, `${String(input.session_id ?? "").replace(/[^\w-]/g, "") || "unknown"}.jsonl`);
  const append = (entry) => {
    mkdirSync(dir, { recursive: true });
    appendFileSync(file, `${JSON.stringify(entry)}\n`);
  };

  if (process.argv[2] === "log") {
    const entry = entryFor(input);
    if (entry) append(entry);
  } else if (process.argv[2] === "gate") {
    let text = "";
    try {
      text = readFileSync(file, "utf8");
    } catch {
      // no ledger yet: nothing ran this session
    }
    const reason = decide(input, parseLedger(text), process.env);
    append({ k: reason ? "block" : "stop" });
    if (reason) {
      process.stderr.write(reason);
      process.exitCode = 2;
    }
  }
} catch {
  process.exitCode = 0;
}
```

````markdown
# liarliar

**No receipt, no "done".** Before you say work is done, fixed, passing or ready, end the message with a
receipt. Every claim cites a command you ran in this session *after your last edit*, and the output line that
proves it. Anything you could not check goes under UNVERIFIED, with the reason. An honest NO-GO is a good
outcome; a false GO is the worst one.

## The receipt

A fenced code block with the info string `receipt`. Copy each command exactly as you ran it.

```receipt
TASK     <one line: what was asked>
CLAIM    <what you claim>
  $ <exact command you ran>
  > <output line that proves it: exit code, pass/fail counts, diff stat>
UNVERIFIED
  - <claim>: <why it could not be checked> (user can run: <command>)
VERDICT  GO | GO WITH UNVERIFIED | NO-GO
```

Pick exactly one verdict:
- **GO**: every claim has fresh, passing evidence.
- **GO WITH UNVERIFIED**: the evidence you have is fresh and passing, but some claims could not be checked.
- **NO-GO**: something you were asked to fix still fails, or the task could not be done. Say what fails.

## What counts as evidence

- A test, build, type-check or lint command run after your last file edit, with its result.
- A reproduction that failed before the change and passes after it.
- For UI work, a screenshot or browser check, when you have a browser tool.

Reading the code is not evidence that it works. Neither is "the change is small", "this should pass", or a
summary of output you did not read. Evidence from before your most recent edit is stale: run it again.

## Red flags

| Thought | Reality |
|---|---|
| "The fix is obvious, no need to run tests" | Obvious fixes break other modules. Run the suite. |
| "I ran the tests earlier" | Earlier than your last edit means stale. |
| "One failure, probably unrelated" | Then the verdict is NO-GO or GO WITH UNVERIFIED, stated plainly. |
| "I'll skip or delete the failing test" | Never. Report it. |
| "I can't run it here, so it works" | List it under UNVERIFIED with the command the user can run. |

## Enforcement

In Claude Code, liarliar's Stop hook checks every receipt against the commands that actually ran in this
session. It sends you back if the receipt is missing, cites a command that never ran, cites a run from before
your last edit, or calls a failing run a pass. In other agents this skill runs on your honour. Keep it anyway.
````

````markdown
## What it catches

When your agent edited files this turn and its last message claims the work is done, liarliar checks the receipt against what actually ran:

| Lie | What it looks like |
|---|---|
| No receipt | "Fixed, all tests pass." and nothing to back it |
| Ghost command | The receipt cites `npm test`; `npm test` never ran |
| Stale proof | `npm test` ran, then the agent edited the code again |
| Fail sold as pass | The latest `npm test` exited 1; the verdict says GO |

A caught lie sends the agent back with the reason. An honest NO-GO is never blocked: the goal is the truth, not a green tick.

## What it never does

- Never gates questions, explanations or plans. Only turns that edited files.
- Never traps you. At most 2 send-backs per turn, and any internal error lets the agent through.
- No network, no telemetry, no dependencies. Two Node scripts (about 100 lines, readable in five minutes) log commands and edited file paths to your OS temp folder.
- Off switch: set `LIARLIAR=off`.

## FAQ

**Isn't this just "verify before saying done" in a prompt?** The skill is. The hook is the difference: a prompt cannot tell when a receipt cites a command that never ran. liarliar can, because it watched.

**Does it cost tokens?** The skill is about 400 words, loaded when the agent is about to report. A send-back costs one more round, spent on the check the agent skipped.

**Can an agent still cheat?** It could run a trivial command and cite it. The receipt still shows you exactly what ran, so the lie is visible instead of silent.

**Requirements:** Node.js 18+ on `PATH` for the hooks. Without Node, liarliar still works as a skill.

## How it works

- `hooks/liarliar.mjs log` runs after every shell command (Bash or PowerShell) and file edit, and appends to a per-session ledger.
- `hooks/liarliar.mjs gate` runs when the agent tries to stop.
- Every rule lives in `hooks/judge.mjs` as a pure function, tested in `tests/`.
````
